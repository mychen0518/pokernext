# 15: 行程申請、行程編號與版本、草稿、同行者

**What to build:** 會員自行填寫行程申請並在送出當下取得行程編號；未取消、未退房前修改沿用原行程 ID 產生新版本；取消後重申或退房後再申請取得新 ID；可登記不打牌的同行者；草稿伺服器保存、版本衝突處理、30 天清理；正式送出自動把售前輪次標為已轉行程。

**Blocked by:** 12（客戶詳情頁、售前輪次與跟進紀錄）、13（玩家端五項主導覽與會員中心（含空狀態、休息提醒偏好））

**Status:** ready-for-agent

**UI:**
- Surface: 玩家端（手機）
- Page type: DESIGN.md §3.1 表單頁 ＋ 我的行程列表
- Reference: `docs/design/references/player-home-mobile.png`
- Prototype: `#/player/trips/new`、`#/player/trips`；actions `applyTrip`
- Components: Select、DateInput×2、Input（航班）、Select（接機偏好，帶入偏好後仍由玩家確認）、Card（住宿需求預覽）、Checkbox（條件同意）、Button/primary（送出）、Tabs/segmented（目前與未來／歷史）
- States: 送出成功即顯示行程編號與「等待管理者核對」；草稿衝突 Modal；護照待補 → Badge/warning「不可送訂」

- [ ] 送出即得行程編號，不等訂房；回程航班可空
- [ ] 修改未取消未退房的行程 → 同 ID 新版本，歷史版本可查；取消後重申或退房後再申請 → 新 ID、UUID 不變（一正一反）
- [ ] 同行者只登記旅客資料與接送需求，不建立會員或住宿兌換資格
- [ ] 草稿與正式行程識別不同；草稿在兩裝置同時編輯時有版本衝突處理；30 天未動的草稿被清理（可控時鐘）
- [ ] 正式送出使該會員的有效售前輪次標為「已轉行程」；草稿不會
- [ ] 護照待補的會員能送出行程需求，但該需求被標示為不可送訂、不占限量活動名額
- [ ] 我的行程頁能列出多個行程並切換，顯示目前檢視的行程編號
- [ ] 送出後行程卡立即出現在「目前與未來」並帶 Badge「已申請 · 待管理者核對」，不顯示任何空的酒店卡
