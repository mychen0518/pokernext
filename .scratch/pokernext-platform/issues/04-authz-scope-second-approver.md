# 04: 角色／範圍／欄位／狀態授權檢查 ＋ 第二人核准框架

**What to build:** 每一次查詢、建立、修改、審批、確認、下載、匯出都同時判斷角色、客戶／行程／案件範圍、欄位與當前狀態，未授權就拒絕而不只是藏按鈕；並提供「重大操作需第二個自然人」的通用核准框架。以一個通用「核准案件」流程走通端到端，後續票沿用。

**Blocked by:** 03（工作帳號邀請、密碼＋TOTP 登入、備援碼與 AuditLog）

**Status:** ready-for-agent

- [ ] 未授權的請求回 403 並留稽核紀錄；同一資料換一個有範圍的帳號請求則成功（一正一反）
- [ ] 開頁與送出各重查一次：開頁後權限被撤銷或資料版本已更新，送出被拒並要求重新查看
- [ ] 第二人核准：提出者與核准者必須是不同自然人；同一人切角色或換 Email 不構成第二人
- [ ] 核准者當下必須仍持有該操作授權；授權已撤銷的核准被拒
- [ ] 核准者是案件受益人時被拒，案件必須交給另一位授權者
- [ ] 沒有適格第二人時案件維持待審；Platform admin 不能宣告跳過
- [ ] 轉派、停權、任務結束或撤銷後立即撤除存取：已開啟的頁面與舊連結再操作時被拒
- [ ] 原始帳目、已支付紀錄、核對確認與稽核紀錄的更新／刪除 API 不存在；業務修正只能走保留歷史的更正／調整
