# 22: 任務核心與 15 個固定範本（T01–T15）

**What to build:** 管理者從 15 個固定範本建立任務，系統自動帶入姓名、正式行程、住宿資料與現有接待人；三種型態（持續追蹤／單次處理／分輪跟進）；接待人先填固定答案與條件欄位再附文字與附件；一個主任務累積多筆不可覆寫回報；正式來源事實成立時自動完成對應任務；任務答案永遠不會驅動正式業務狀態。

**Blocked by:** 20（現場事實事件與服務生命週期投影）、21（續住、入住前改期、取消流程與琪琪行程異動佇列）

**Status:** ready-for-agent

**UI:**
- Surface: 接待端（接待工作區，手機，我的任務）＋ 管理端（管理工作區，任務與異常）
- Page type: 接待端 no precedent → /prototype first（DESIGN.md §3.3）；列表＋任務明細固定布局（PRD 8.2：參照 → 來源狀態 → 固定答案 → 條件欄位 → 補充 → 提交）
- Reference: `docs/design/references/player-home-mobile.png`（手機 token）；管理端用 `partner-overview.png` 的 DataTable
- Prototype: `#/staff/tasks`、`#/staff/tasks/TSK-1043`、`#/admin/tasks`；actions `submitTask`, `newTask`
- Components: 員工端 seg（進行中／已完成／全部）、ListItem（Badge T06 + 標題 + 期限）、Card（客戶與業務參照）、Card（來源狀態／既有回報）、Radio（固定答案）、依答案展開的 Input（實際時間、來源）、Textarea、Button/primary/m block（提交回報，未選答案時 disabled）；管理端 DataTable/dense、Modal（建立任務：範本／行程／指派）
- States: 肯定答案未填實際時間 → 欄位錯誤態；否定／未知答案 → 展開「下一步／下次跟進時間」；已由正式來源自動完成的任務顯示依據與時間

- [ ] 15 個範本各有版本；任務綁定建立時的範本版本，新版本不改舊回報含義
- [ ] 建立與提醒啟動分開：9/20 入住的行程可在 9/10 建立 T06，到追蹤時間才提醒（可控時鐘）
- [ ] 同範本＋同客戶＋同業務事項最多一個進行中主任務；每日提醒或重試不產生重複
- [ ] 答案必須是固定選項；「確認尚未發生」與「尚未核實」是不同答案、不能互換、不預填否定；自由文字不能替代答案
- [ ] 回報「已入住」必須附實際入住時間與查證來源，否則被拒
- [ ] 持續追蹤型未完成時必須填下一步與下次跟進時間
- [ ] 新回報不覆寫既有回報；與正式事實衝突時列為待核實
- [ ] 正式來源事實（例如第 20 票的入住事件）成立時對應任務自動完成，不再要求重複回報
- [ ] 行程接待轉派時未完任務一起移交，完成歷史保留原執行人；取消完成後依範圍撤銷任務、保留回報；取消中僅暫停
- [ ] 沒有通用「強制完成」API；Platform admin 無法增刪核心答案、必要證據欄位或型態與正式狀態的映射
- [ ] 一般任務表單沒有改積分、改歸屬、已收／已退押金、代玩家同意這些結果
- [ ] T12 實際離島核實：無回程時以退房次日建立，仍在島／未確認時維持同一任務不每天重建
- [ ] 固定答案為 Radio 且不預選；肯定答案的必填欄位標 * 並在空白時阻擋提交

**Notes:** G20：實際案件文案與通道端到端實測未定；本票交付範本結構與契約，文案為可替換資源。
