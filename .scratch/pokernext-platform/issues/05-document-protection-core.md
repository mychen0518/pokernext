# 05: 文件保護核心：信封加密／KMS 埠、HMAC 查找索引、限時查看、故障暫停

**What to build:** 任何人上傳一份附件（或填寫一個敏感欄位）後，資料以 AES-256-GCM 信封加密保存，KMS 保管 KEK；授權者可在 5 分鐘窗口內查看，到期或鎖定立即遮蔽；加解密故障時暫停受影響操作而不是退回明文。同時提供證件號／Email／手機的受控 HMAC 查找索引，讓後續重複檢查不用密文比對。

**Blocked by:** 03（工作帳號邀請、密碼＋TOTP 登入、備援碼與 AuditLog）

**Status:** ready-for-agent

- [ ] 上傳的附件在儲存層是密文；信封含加密格式版本、物件版本、KMS key/version reference、wrapped DEK、nonce／tag、AAD
- [ ] 每份文件／敏感資料版本一把獨立 DEK；同一金鑰下 nonce 不重複，有測試證明
- [ ] AAD 綁定穩定主體與文件版本，不綁 Agent、行程歸屬或 Email
- [ ] 授權者開啟敏感欄位或附件後最多可看 5 分鐘；到期、登出或鎖定後再讀取被拒並遮蔽
- [ ] 假 KMS 注入「無法包裝 DEK」時，上傳不標示成功、不改存明文；注入「無法解密」時，不顯示圖片並讓依賴原圖的操作進入暫停
- [ ] 加解密故障只限制實際受影響的操作，同時通知管理者與 Platform admin 並留下事件紀錄；其他功能照常
- [ ] 沒有任何「關閉加密」「繞過 KMS」的 API 或設定
- [ ] 證件號／Email／手機以受控正規化＋獨立金鑰 HMAC 建立查找索引；索引只產生候選，不做自動合併；不存在明文索引或無金鑰雜湊
- [ ] 日誌不寫完整證件、OCR 原文、可直接讀檔的連結或金鑰
- [ ] Platform admin 的業務權限不等於 KMS 管理權：Platform admin 帳號無法任意解密
- [ ] 輪替、重新包裝 DEK、重新加密、暫停金鑰、永久銷毀是五個不同操作；金鑰輪替後舊資料仍可解密

**Notes:** G22：實際 KMS／OCR 供應商、輪替週期等參數未定；本票以假 KMS 埠實作，輪替週期為可設定項而非寫死數值。
