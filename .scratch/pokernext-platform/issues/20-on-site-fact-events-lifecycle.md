# 20: 現場事實事件與服務生命週期投影

**What to build:** 接待人在手機工作台回報接到本人、上車、抵達酒店、酒店實際入住、實際退房、場館到場六類事件，每件各自保存實際發生時間、查證時間、回報時間、操作者、來源與版本；「在島內」由酒店實際入住產生、「已離境（營運）」由實際退房產生，兩者都是衍生投影而不是可選的狀態欄位。

**Blocked by:** 16（訂房訂車核對、酒店預訂單四狀態與本人一間房逐晚防重）、19（到場短效 QR 與櫃檯報到防重（含人工核對入口））

**Status:** ready-for-agent

- [ ] 六類事件各自保存實際／查證／回報三個時間與來源；預計時間不能寫入實際欄位、系統時間不能代替現場時間（一正一反）
- [ ] 酒店入住事件成立後行程顯示「在島內」；沒有入住事件時不顯示（沒有任何 API 能直接設定在島內）
- [ ] 酒店 Check-in 不產生 PokerRoom 到場；到場只來自授權人工回報或第 19 票的櫃檯確認
- [ ] 實際退房事件成立後行程按「已離境（營運）」處理，續住／改期入口關閉；只保存退房事件為依據，不寫入搭機或出入境事實
- [ ] 預計退房／航班時間到了但沒有退房回報：只產生提醒，行程不自動終止（可控時鐘）
- [ ] 已退房但仍在濟州的會員要安排新住宿必須重新申請新行程；舊行程不能重開
- [ ] 接機與送機各自獨立；退房不推定送機完成；送機標示為玩家自付車方
- [ ] 提交取消、琪琪開始執行與實際入住回報互相衝突時，行程顯示待核實而不是任一方單獨生效
- [ ] 營運已離境成立時會員收到服務結束與積分摘要通知，文案不宣稱已搭機、不把未結算餘額稱為最終餘額
