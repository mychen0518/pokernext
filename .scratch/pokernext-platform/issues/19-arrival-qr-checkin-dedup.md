# 19: 到場短效 QR 與櫃檯報到防重（含人工核對入口）

**What to build:** 會員在到場碼頁取得本次天城行程的短效 QR；櫃檯掃碼後看到護照英文姓名與四項核對資料（行程編號、天城會員編號、UUID、該行程有效住宿確認編號）以及是否已報到；以固定三選項核對本人後按「確認到場報到」；每會員／每場館／每行程只有一筆有效報到，重送、換新 QR、跨日重掃、兩名櫃檯同時確認都不建立第二筆。

**Blocked by:** 13（玩家端五項主導覽與會員中心（含空狀態、休息提醒偏好））、18（天城合作端帳號、閒置鎖定、五類分項授權與可見範圍）

**Status:** ready-for-agent

**UI:**
- Surface: 玩家端（到場碼頁，手機）＋ 合作端（櫃檯掃碼，桌面）
- Page type: 玩家端單欄；合作端 DESIGN.md §3.2 作業頁
- Reference: `docs/design/references/partner-checkin.png`
- Prototype: `#/player/qr`、`#/venue/checkin`、`#/venue/checkin/TR-260911-028`；actions `venueCheckin`
- Components: 玩家端 Card（QR、短效碼、本行程報到狀態）；合作端 ResultBanner（掃碼成功＋行程編號＋狀態）、KeyValueList/inline（UUID 全文、天城會員編號、行程、住宿確認編號、日期、晚數）、split（酒店入住／PokerRoom 兩個獨立狀態）、Radio 三選項（已核實／暫無法核實／疑似非本人）、Button/primary（確認到場報到，未核實時 disabled）
- States: 已報到重掃 → InfoBox「本行程已於 <時間> 完成到場報到」且無第二次按鈕；日期不在行程期間 → ResultBanner/error；相機／網路失敗 → 未完成提示

- [ ] 到場碼頁在有有效行程時顯示短效 QR；沒有有效行程時顯示原因說明
- [ ] 掃碼只顯示資料，不自動報到；本人核對只能選「已核實／暫無法核實／疑似非本人或資料不符」
- [ ] 確認後建立 (member_uuid, venue, trip_id) 唯一有效報到；資料庫層約束
- [ ] 重送、換新 QR、跨日重掃、兩名櫃檯並發確認（併發測試）都回傳既有報到與原確認人，不建第二筆
- [ ] 已報到的玩家重掃時顯示「本行程已於 <時間> 完成到場報到」，不顯示第二次報到按鈕
- [ ] 操作日期不在所選行程日期期間時提示選錯行程，不自動放行、不改行程日期
- [ ] 經專項授權的人員可在有效行程期間按次限時 5 分鐘查看護照原圖，不能下載；未授權者被拒
- [ ] 人工核對入口（玩家手機沒電）與掃碼共用同一報到規則與唯一約束
- [ ] 相機或網路失敗時顯示未完成；確認回應中斷後以操作識別查詢既有結果，不重建
- [ ] 同一行程再次來打牌不需重掃
- [ ] 本人核對為三選項 Radio（不預設勾選）；只有選「已核實」時主按鈕才啟用

**Notes:** G18：實機相機與本人核對 SOP 未定；本票交付 API 與最小網頁介面，正式現場介面在第 30 票。
